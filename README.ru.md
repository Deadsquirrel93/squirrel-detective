# Squirrel Detective

Squirrel Detective — полностью офлайновый Android-аудитор уже установленных приложений. Перебирает локально все установленные пакеты и подсвечивает те, что могут молча сканировать другие приложения и активность пользователя на устройстве. Приложение спроектировано как privacy-first: оно не делает ни одного сетевого запроса, не содержит аналитики и ничего не сохраняет вне устройства.

Squirrel Detective — open source-проект. В нём нет рекламы, трекинга, аналитики, подписок и встроенной монетизации.

Лицензия: `MIT`

Официальный репозиторий: [github.com/Deadsquirrel93/squirrel-detective](https://github.com/Deadsquirrel93/squirrel-detective)

Официальные сборки и обновления Squirrel Detective распространяются только через этот репозиторий. Если APK или обновление пришло из любого другого источника — это не официальный релиз.

## Что приложение делает

Squirrel Detective позволяет:

- сканировать каждое установленное приложение, опционально включая системные
- смотреть одно конкретное приложение, не запуская полный скан
- видеть для каждого приложения уровень риска (`ВЫСОКИЙ` / `СРЕДНИЙ` / `ОЖИДАЕМ` / `БЕЗОПАСНО`) и объяснение для каждой найденной причины человеческим языком
- читать все Android-разрешения, которые объявило приложение
- читать все пакетные broadcast-receiver'ы, объявленные приложением (`PACKAGE_ADDED` / `PACKAGE_REMOVED` / `BOOT_COMPLETED`)
- из любого отчёта одним нажатием попадать в системные настройки этого приложения, чтобы отозвать разрешения или удалить его
- сравнивать сканы: если приложение получило новые чувствительные разрешения или находки с прошлого раза, это видно, пока вы не откроете баннер изменений
- видеть, объявлена ли у приложения служба специальных возможностей, администратор устройства, клавиатура или доступ к уведомлениям — или она включена прямо сейчас
- открыть встроенную «Wiki по разрешениям» и прочесть на простом языке, что реально даёт каждое Android-разрешение
- переключать интерфейс между русским и английским в любой момент

## Что приложение детектит

Детектор не использует удалённую базу сигнатур — все решения принимаются локально, на основе того, что объявлено в манифесте приложения.

### Опасные комбинации разрешений

- `QUERY_ALL_PACKAGES + INTERNET` — может перечислить все приложения и отправить список наружу
- `READ_LOGS` (особенно вместе с `INTERNET`) — может на не-rooted устройстве отслеживать запуски приложений и intents
- `BIND_ACCESSIBILITY_SERVICE` — самый мощный канал слежки на Android (читает любой экран, эмулирует жесты)
- `BIND_DEVICE_ADMIN` — права администратора устройства (блокировка, политика паролей, на старом Android — сброс)
- `BIND_NOTIFICATION_LISTENER_SERVICE` — читает все уведомления, включая SMS-коды и оповещения банков
- `BIND_VPN_SERVICE` — заворачивает весь трафик устройства через приложение
- `BIND_INPUT_METHOD` — клавиатура, видит каждое нажатие

Пять `BIND_*`-возможностей выше определяются по компонентам, которые приложение действительно объявляет: `<service>` (а для администратора устройства — `<receiver>`), защищённый этим разрешением. Просто указать `BIND_*` в `<uses-permission>` стороннему приложению ничего не даёт, и такое не флагается.

Объявленный компонент ничего не может, пока вы не включите его в системных настройках, поэтому Squirrel Detective дополнительно проверяет, что включено прямо сейчас:

| Возможность | Объявлена | Включена прямо сейчас |
|---|---|---|
| Служба специальных возможностей | `СРЕДНИЙ` | отдельная находка `ВЫСОКИЙ` |
| Администратор устройства | `СРЕДНИЙ` | отдельная находка `ВЫСОКИЙ` |
| Доступ к уведомлениям | `СРЕДНИЙ` | отдельная находка `ВЫСОКИЙ` |
| Клавиатура (способ ввода) | `СРЕДНИЙ` | отдельная находка `ВЫСОКИЙ` |
| VPN-служба | `СРЕДНИЙ` | не определяется |

Состояние «включено» берётся из публичных API Android и не требует дополнительных разрешений. Android не сообщает другим приложениям, чья VPN сейчас активна, поэтому VPN всегда показывается как «объявлена». Системные приложения не поднимаются выше `СРЕДНИЙ`, whitelist остаётся `ОЖИДАЕМ`.

- `SYSTEM_ALERT_WINDOW` — рисование поверх других приложений
- `PACKAGE_USAGE_STATS` — история использования всех приложений
- `REQUEST_INSTALL_PACKAGES` — установка APK помимо Google Play
- `RECORD_AUDIO + INTERNET`, `CAMERA + INTERNET`
- SMS-группа (`READ_SMS`, `RECEIVE_SMS`, `SEND_SMS`, `RECEIVE_MMS`, `RECEIVE_WAP_PUSH`)
- Группа журнала звонков (`READ_CALL_LOG`, `WRITE_CALL_LOG`, `PROCESS_OUTGOING_CALLS`)
- `READ_CONTACTS + INTERNET`
- Геолокация (`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`) вместе с `INTERNET`
- `READ_PHONE_STATE` / `READ_PHONE_NUMBERS`
- `MANAGE_EXTERNAL_STORAGE`
- `WRITE_SETTINGS` / `WRITE_SECURE_SETTINGS`
- `GET_TASKS` / `REAL_GET_TASKS` у несистемных приложений
- `GET_ACCOUNTS + INTERNET`

### Подозрительные broadcast-receiver'ы

- `ACTION_PACKAGE_ADDED` — приложение получает уведомление о любой установке
- `ACTION_PACKAGE_REMOVED` — приложение получает уведомление о любом удалении
- `BOOT_COMPLETED` в комбинации с доступом к списку пакетов или к статистике использования — типичный сигнал фонового сканирования

### Прочие признаки сборки и установки

- приложение помечено как `debuggable` в релизной сборке
- приложение нацелено на устаревший SDK (ниже API 23) и обходит модель runtime-разрешений
- скрытое приложение (нет launcher-активити) с чувствительными разрешениями — типичный паттерн stalkerware
- sideloaded-приложение (неизвестный installer) сразу с несколькими опасными разрешениями

### Whitelist

Лаунчеры, магазины приложений, файловые менеджеры и антивирусы распознаются и понижаются до уровня `ОЖИДАЕМ` (зелёный) с пояснением, чтобы отчёт оставался сфокусированным на тех приложениях, которые действительно стоит проверить.

Одного известного имени пакета недостаточно — его может повторить любой APK, установленный вручную. Понижение применяется только к системным приложениям и к установленным из доверенного магазина (Google Play, Galaxy Store, AppGallery, Xiaomi, Amazon, RuStore, F-Droid, Aurora Store). На Android 11+ магазин определяется по пакету, который фактически выполнил установку, — само приложение подделать его не может.

## Модель приватности

Squirrel Detective построен по строгой офлайновой и read-only модели:

- у приложения нет разрешения `INTERNET` и оно физически не делает сетевых запросов
- ничего о просканированных приложениях не покидает устройство
- единственная локальная персистенция — Room-база с базовым снимком скана, нужная только для diff'а
- эта база исключена из облачного резервного копирования Android и из переноса на новое устройство, так что список ваших приложений не попадает в бэкап
- приложение объявляет `QUERY_ALL_PACKAGES`, потому что начиная с Android 11 это единственный способ получить полный список установленных пакетов — без этого аудитор не может выполнить свою работу

## Основные возможности

### Полный скан

Перебирает каждое установленное приложение, классифицирует его и показывает отчёт, сгруппированный по уровню риска. Системные приложения можно опционально включить в скан.

### Скан одного приложения

Выберите конкретное установленное приложение и посмотрите его разрешения, receiver'ы и причины риска, не запуская полный скан устройства.

### Подробный экран

Для каждого приложения отчёт показывает:

- агрегированный уровень риска
- каждую найденную причину с коротким заголовком и развёрнутым человеческим объяснением
- полный список объявленных разрешений (текст можно выделить — каждое разрешение копируется одним движением)
- broadcast-receiver'ы и actions, на которые они подписаны
- кнопку для перехода в системные настройки этого приложения, чтобы отозвать разрешения или удалить его

### Diff между сканами

Каждый скан сравнивается с базовым снимком из локальной Room-базы. Если что-то изменилось, баннер показывает, сколько приложений затронуто. Если его раскрыть, по каждому приложению видны новые находки (например, только что включённая служба специальных возможностей) и добавленные или удалённые разрешения; тап по приложению открывает его детальный экран.

Баннер держится, пока вы его не раскроете: если закрыть приложение или Android выгрузит его в фоне раньше, следующий скан покажет те же изменения. Раскрытие баннера отмечает изменения как просмотренные и сдвигает базу. Если изменение откатилось до того, как вы его увидели (службу снова выключили), оно просто пропадёт из баннера.

Сканирование запускается только вручную — фонового ре-скана нет.

### Wiki по разрешениям

Встроенный справочник: что реально даёт каждое Android-разрешение. Категории: Наблюдение, Мощные системные сервисы, Сенсоры, Связь и идентификация, Геолокация, Хранилище, Система. По каждому разрешению — что оно позволяет, зачем его законно просят и когда оно подозрительно.

### Локализация

Русский и английский. По умолчанию используется язык системы; выбрать язык можно в настройках приложения или, на Android 13+, в системной настройке языка приложения. Выбор применяется сразу и сохраняется между запусками.

## Подпись APK

Официальные APK (начиная с 1.0.0) подписаны ключом, который сгенерирован на машине разработчика и существует только там. Это keystore в формате debug-ключа Android SDK (сертификат `CN=Android Debug, O=Android, C=US`), но каждая машина генерирует свой случайный debug-ключ, поэтому никто другой не сможет выпустить сборку, которая встанет «обновлением» поверх официальной.

Официальные сборки всегда подписывались этим ключом, поэтому каждый новый релиз ставится поверх предыдущего с сохранением данных. У нового сертификата в Play Protect тоже не было бы репутации, а смена ключа заставила бы всех пользователей сначала удалить приложение.

SHA-256 сертификата подписи:

```
DB:AD:E5:21:40:5C:EC:12:11:D3:B1:42:2D:CC:05:80:36:44:6C:1D:08:D2:02:35:A7:26:82:17:4C:1A:94:CF
```

Проверить скачанный APK можно утилитой `apksigner` из build-tools Android SDK:

```bash
apksigner verify --print-certs squirrel-detective-2.0.0.apk
```

Строка `Signer #1 certificate SHA-256 digest` должна совпасть со значением выше (в нижнем регистре и без двоеточий). Если не совпадает — это не официальная сборка.

Сборка, которую вы соберёте сами, подписывается debug-ключом вашей машины. Поверх официальной её можно поставить только после удаления официальной.

## Установка

1. Скачайте `squirrel-detective-<версия>.apk` из последнего [GitHub Release](https://github.com/Deadsquirrel93/squirrel-detective/releases). При желании сверьте его SHA-256 с указанным в release notes и проверьте сертификат подписи (см. [Подпись APK](#подпись-apk)).
2. Когда устройство попросит — разрешите установку из источника, через который вы скачали APK (браузер или файловый менеджер).
3. Откройте APK и подтвердите установку.
4. Запустите Squirrel Detective и нажмите **Начать сканирование**.

Обновление с прошлого официального релиза: установите новый APK поверх старого, данные сохранятся.

Play Protect может предупредить о неизвестном приложении при sideload-установке. Нажмите **Подробнее** → **Всё равно установить**.

На стороне устройства нужны:

- `QUERY_ALL_PACKAGES` — объявляется автоматически, действий от пользователя не требуется
- больше ничего

## Ограничения

- Squirrel Detective видит то, что объявлено в манифесте каждого установленного приложения, а также какие службы специальных возможностей, администраторы устройства, клавиатуры и доступы к уведомлениям включены прямо сейчас. Он не наблюдает сетевой трафик, не перехватывает системные вызовы и не анализирует байткод APK в рантайме.
- Владелец активной VPN другим приложениям не виден, поэтому VPN-службы всегда показываются как «объявлены».
- Переключение между сканом с системными приложениями и без них сбрасывает из базы неподтверждённые изменения системных приложений.
- Иконки приложений кэшируются на время жизни процесса; приложение, обновлённое, пока Squirrel Detective запущен, может показываться со старой иконкой до перезапуска.
- Статический анализ манифеста не говорит, что приложение *делает* с разрешением, когда его выдали — только что оно *может* делать.
- `INTERNET` — это обычное install-time разрешение, само по себе оно не считается находкой; учитывается только в комбинациях с чувствительными разрешениями на чтение данных.
- Приложение нельзя распространять через Google Play, потому что `QUERY_ALL_PACKAGES` там ограничено.
